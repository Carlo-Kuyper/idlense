# Adding or porting a country

This library has **no runtime dependencies**. All rules live in `src/countries/<alpha2>.ts`.
Several open-source libraries were the starting point (see `THIRD_PARTY_NOTICES.md`). We port
their logic, check it against the issuer's own rules, and fix it where it's wrong.

Reference implementations: `src/countries/za.ts` and `src/countries/no.ts`, with tests in
`test/countries/za.test.ts` and `test/countries/no.test.ts`. Copy their shape.

## Files

| File | What |
|---|---|
| `src/countries/<cc>.ts` | `export const documents: DocumentSpec[]`, one entry per document type. `<cc>` is lowercase ISO alpha-2. |
| `test/countries/<cc>.test.ts` | `describeContract(documents)` + extraction tests + upstream comparison. |

`src/countries/index.ts` is generated by `pnpm gen` from the files present. Don't edit it.

## The contract (`src/core/types.ts`)

- `code` is `{ALPHA2}_{TYPE}`, uppercase, stable forever. If nationid already has a code for the
  same document, **reuse nationid's code** (`BR_CPF`, `MX_CURP`, `ES_NIE`, ...) so callers can migrate.
  Otherwise use the local acronym (`PL_PESEL`, `SE_PERSONNUMMER`, `CN_RIC`, `KR_RRN`).
- `purpose`: `identity` (national ID / personal number), `social_security`, `migratory`
  (foreigners' numbers), `tax`, `voter`, `driver_license`, `passport`, `health`.
- `holder`: `person`, `entity` (company/VAT), or `both` (e.g. a tax number issued to both).
- `checksum: true` only if `parse` verifies a check digit/letter. Shape-only documents are
  `false`; `identify()` skips them when guessing the country.
- `checkIndex` / `checkUnique`: when the check character isn't last (e.g. `-3` for Zimbabwe,
  `8` for AU Medicare) or more than one value can pass (Taiwan UBN). The contract tests use them.
  If the issuer says the check is not mandatory for some numbers (Ecuador company RUCs), accept
  them and return `extra.checkDigitValid: false`: `identify()` then reports `checksumVerified: false`
  for that number and ignores it when guessing the country.
- `confidence`: `high` = issuer/law publishes the rule and it is cross-checked; `moderate` =
  consistent secondary sources; `low` = single/reverse-engineered source.
- `lengths` (compact lengths) and `pattern` (compact form). `runDocument` reports
  `invalid_length` then `invalid_format` before calling `parse`. Make `pattern` as tight as
  the structure allows: month 01-12, region code ranges, letter positions, etc.
- `normalize`: default `compact()` removes whitespace and `. - / ( ) , _ :` and uppercases
  ASCII. Use `digitsOnly` for all-digit numbers, or `compactKeeping(input, "-+")` when a
  separator carries meaning (Finland's century sign, Sweden's `+` for 100+).
- `format`: the conventional display form. Must round-trip: `parse(normalize(format(x)))` is valid.
- `example`: a valid compact number. Synthetic, or an issuer's published specimen. Never a real person's.
- `sources`: issuer page / law / official spec first, then Wikipedia or similar. At least one.
- `upstream`: which ported projects the logic came from.
- `parse(compact, { referenceDate })`: returns `{ ok: true, data }` or `{ ok: false, reason }`.

### Reasons

`invalid_date` (impossible or future birth date) · `invalid_checksum` · `invalid_range`
(structurally fine but in an unissued/reserved range: SSN area 000/666/9xx, unknown region code,
unissued Norwegian century range) · `invalid_format` (anything else structural).

### Extracted data

Fill only what the number really encodes:

- `dateOfBirth` `YYYY-MM-DD` + `birthYear`: use `birthFields(y, m, d, referenceDate)`, which
  rejects impossible and future dates. If the century isn't encoded, use
  `latestPastYear(yy, m, d, referenceDate)`. **Never** build a `Date` and read it back:
  timezone shifts are the main bug in idnumbers.
- `birthYear` alone when only the year is encoded.
- `gender`: `male` | `female` only.
- `citizenship`: snake_case, e.g. `citizen`, `permanent_resident`, `foreigner`, `refugee`.
- `region` = the raw code. `regionName` only from a small table you have a source for.
- `serial` = the sequence part.
- `extra`: camelCase keys, string/number/boolean only. Use it for things like `kind: "d-number"`
  or `checkDigit`.

## Improving on upstream

The ported logic is a starting point, not the truth. For each document:

1. Read upstream's implementation and tests (paths below).
2. Check the rules against the issuer/legal source. Wikipedia's national-ID pages are a
   good index to the official specs.
3. Fix what upstream gets wrong. Typical bugs: timezone-shifted dates, accepting future birth
   dates, wrong century tables, missing variants (foreigner numbers, 100+ year olds), reserved
   ranges not rejected, case-sensitive letters, crashes on bad input.
4. Write each fix in the module header under **"Improves on upstream:"**.
5. Add documents upstream lacks where there's a solid source.

Licensing: port only from the MIT/ISC projects listed in `THIRD_PARTY_NOTICES.md`. **Do not copy
code from python-stdnum (LGPL) or any GPL project.** Reading their docs/tests to understand an
algorithm is fine; the algorithm itself isn't copyrightable, but the code is.

## Tests

```ts
import { documents } from "../../src/countries/xx.js";
import { describeContract } from "../helpers/contract.js";
import { check, compareWithOracle, fromTemplate, REF, spec } from "../helpers/oracle.js";

describeContract(documents);
```

- Extraction tests with `check(spec(documents, "XX_CODE"), input)`: known-good numbers with
  every field asserted, plus each rejection reason.
- **Upstream comparison** for ported documents: `compareWithOracle({ spec, generate, samples, allow })`.
  It replays upstream's verdicts recorded in `test/fixtures/upstream/<file>.json`, so no upstream
  package is installed. `generate` must yield a good share of valid numbers (assert
  `validSeen > 20`). `allow` may only excuse disagreements that are deliberate fixes, keyed on
  *our* rejection reason or the specific rule you changed; `res.unexplained` must be `[]`.
  Fixtures are keyed by test name and fail as "stale" if the generator, seed or sample count
  changes. Don't rename a comparison test without re-recording it.

  To compare against a new upstream library:
  1. `pnpm add -D <package>` and pass `oracle: (s) => upstreamValidate(s)`.
  2. `UPSTREAM_RECORD=1 pnpm exec vitest run test/countries/xx.test.ts` to save its verdicts.
  3. Remove the `oracle` argument and its import, then `pnpm remove <package>`.

Run only your own files while other work is in progress:

```sh
pnpm exec vitest run test/countries/xx.test.ts
pnpm exec tsc --noEmit 2>&1 | grep "countries/xx"
```

Don't edit shared files (`src/core/*`, `src/identify.ts`, `test/helpers/*`, `package.json`). If you
need a helper that isn't there, write it in your country file and mention it in your report.
